End-to-end pipeline run
======================

Produced by tests/e2e_pipeline.py, which starts the real FastAPI app, posts one
image to /pipeline/image-to-cards, and reports what came back.

Conditions:
  host     gary, Intel UHD Graphics CML GT2 (Gen9.5), the project's target
  runtime  llama.cpp b11577, Vulkan backend, the asset the Linux build downloads
  model    gemma-4-e2b-it-q4_0.gguf + mmproj, context 8192
  image    a handwritten French vocabulary page, downscaled to 768px as the app does

This is the only check in the repository that runs the pieces together. Two
faults were found by it that no component test could have caught, both fixed
and both verified by the run recorded here:

  1. The pipeline split OCR output on newlines, but the model transcribes what
     it sees, so a page whose entries are comma-separated came back
     comma-separated and each line became one card holding three words.
     Eleven mis-grouped items are now twenty-eight individual words.
  2. The vision generation budget was 512 tokens. On this page the model's
     reasoning ran past it, the channel never closed, and the OCR returned
     nothing at all. Raised to 1024.

Known, not fixed here: the pipeline takes the first twenty words and drops the
rest without saying so. This page yields twenty-eight, so eight never reach a
card. And most cards carry an 'untranslated' warning because the model writes
English example sentences with the source word left inside them, which the
warning is correctly pointing at.
