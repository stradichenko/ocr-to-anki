End-to-end pipeline run, after the fixes
========================================

Produced by tests/e2e_pipeline.py against the real backend.
Same conditions as the earlier run: gary, Intel Gen9.5, llama.cpp b11577 on
Vulkan, gemma-4-e2b, one handwritten French vocabulary page downscaled to 768px.

What changed since the first run, and what this run shows:

  Word splitting. The OCR text is transcribed as the page is written, so its
  entries arrive comma-separated. Splitting on newlines made one card out of
  three words. Now 28 individual words are enriched instead of 11.

  Truncation. The pipeline took the first 20 words and said nothing about the
  rest. The bound is now 40 and named, and a page longer than it says so in
  the response rather than letting the missing cards look like a read failure.

  Example sentences. The model was writing English sentences with the source
  word left inside them ('The assaillant force attacked'), which the
  untranslated warning then flagged on almost every card. The prompt now
  requires the examples to read naturally on their own. In this run 0 of the
  sampled examples contain their source word, and only one card carries any
  warning at all.

  Vision budget. Raised from 512 tokens, which the model's own narration could
  exhaust before emitting any transcription.

  Server startup. Raised from 90 s. The log for this run records the model
  taking 172.2 s to load, so the old timeout could not have been met.

The cost of the quality fix, stated plainly: this run took 974 s against 563 s
for the earlier one. Two reasons, both real. It now enriches 28 words rather

off or missing. The retry pass is what turns that into 27 usable cards.
