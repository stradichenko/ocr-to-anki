Enrichment batch-size benchmark
================================

Produced by tests/benchmark_enrich.py, driving the real prompt builders,
batch-size helper and parser against a live llama-server.

Conditions for this run (job f6631589):
  host        VM 200, 4 cores, RTX 2070 present but not used
  runtime     llama.cpp b11577 prebuilt, the asset the Linux build downloads
  model       gemma-4-e2b-it-q4_0.gguf, context 8192
  decode      ~11 tokens/sec, flat across every batch size, consistent with
              CPU inference; llama-cli --list-devices reports no device on
              this host, so the Vulkan backend did not engage.

The conclusion does not depend on the device. Prompt evaluation is a fixed
cost per request, so batching amortises it on any hardware; the numbers below
show that cost holding at roughly 9 seconds per call from batch 1 through
batch 8 while the per-word share falls with the batch size.

The absolute saving is larger on the project's target hardware, where the
repository measures prompt evaluation at about 2.5 tokens/sec rather than the
~30 tokens/sec implied here. That figure is an extrapolation from the two
measurements, not something measured on the iGPU.
